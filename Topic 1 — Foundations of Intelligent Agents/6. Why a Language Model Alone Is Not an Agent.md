

Imagine a genius locked in a room with **one small mail slot** in the door.

You slide a note in. A note slides back out.

The note might say: **"Turn off the stove, the house is burning!"**

But nothing happens. The genius has no hands. Somebody **outside the room** has to read the note, walk to the kitchen, turn off the stove, then write "stove is off" on a new note and slide it back in.

The genius is the AI model. **You are the person outside the room.**

Without you, the genius just produces notes forever and nothing in the world ever changes.

---

## Simple technical version

One call to an AI model is:

> **one input → one output → nothing happens in the real world.**

That's it. No action. No memory. No second step.

To turn that into an agent, you must add **five** things — and the model provides **none** of them:

|#|What's missing|What it means|What breaks without it|
|---|---|---|---|
|1|**A loop**|Call the model again and again|You get one reply and stop. Any task needing 2 steps fails.|
|2|**Tools**|Something that actually acts|The AI only describes actions. Nothing happens.|
|3|**Feedback**|Results go back into the input|The AI can't tell if its action worked. It's guessing blind.|
|4|**State**|Remember what's happened so far|Every step starts from zero. It repeats itself forever.|
|5|**Control**|When to stop, what's allowed, what it can spend|It loops forever and runs up a bill.|

So:

```
AGENT  =  model  +  loop  +  tools  +  state  +  control
             ↑        └────────┬─────────────────┘
          vendor's           yours
```

**The vendor gives you one-fifth. You build the rest.** That's the whole project.

---

### The most important idea in this whole topic

Look at where the AI stops and you begin:

```
AI says:  "I want to call  send_email(to='boss@x.com')"
                          │
                          │  ← THE GAP
                          ↓
Your code:  Is send_email a real tool?      → validate
            Is this agent allowed to email? → permission
            Has it already sent this one?   → duplicate check
            Do we have budget left?         → limits
            Should a human approve first?   → approval
            Write down "about to send"      → crash safety
            ─────────────────────────────
            NOW actually send it
```

That gap — between **the AI asking** and **the thing happening** — is where your entire runtime lives.

A model with no gap is a chatbot. A model with a gap you control is an agent.

## Code

### What one model call really is

```python
reply = model.generate("What's the weather in Mumbai?")
print(reply)
# "I don't have access to live weather data."
```

Done. The program ends. Nothing happened. **This is not an agent.** It's one question and one answer.

### Add a tool — still not an agent

```python
def get_weather(city):
    return f"{city}: 31°C, humid"

reply = model.generate("What's the weather in Mumbai?", tools=[get_weather])

if reply.tool_call:
    result = get_weather(**reply.tool_call.arguments)
    print(result)          # "Mumbai: 31°C, humid"
```

Better — something actually happened. But it's **still not an agent**, because:

- The result never went **back to the AI**, so it can't use it in an answer.
- There's **no second step**. If the AI needed another tool, too bad.

### Now make it an agent

```python
def run_agent(question, tools, max_steps=10):
    context = [{"role": "user", "content": question}]
    spent = 0

    for step in range(max_steps):                      # 1. THE LOOP

        reply = model.generate(context, tools=tools)
        spent += reply.cost                            # 5. CONTROL
        if spent > MAX_COST:
            return "Stopped: out of budget."

        if reply.tool_call is None:
            return reply.text                          # finished

        name = reply.tool_call.name
        if name not in tools:                          # 5. CONTROL
            result = f"Error: no tool named {name}"
        else:
            result = tools[name](**reply.tool_call.arguments)   # 2. TOOLS

        context.append({"role": "assistant", "content": reply.raw})  # 4. STATE
        context.append({"role": "tool", "content": str(result)})     # 3. FEEDBACK

    return "Stopped: too many steps."                  # 5. CONTROL
```

All five pieces are now in there, and **every one of them is your code**. The only vendor line is `model.generate(...)`.

### What it looks like when it runs

```
step 1  AI: "I need the weather"  → calls get_weather("Mumbai")
        tool result: "31°C, humid"        ← fed back in
step 2  AI: "I need the forecast" → calls get_forecast("Mumbai")
        tool result: "rain tomorrow"      ← fed back in
step 3  AI: "It's 31°C and humid, rain expected tomorrow."  → done
```

Three model calls. Two tool runs. One answer. **The AI decided all of it — but your code ran all of it.**

## Real-life examples

### How Claude does it

Same model, different harness, completely different capability:

- **In a plain chat with no tools**, if you'd asked for study notes, all I could do is print the text in my reply. You'd have to copy-paste it yourself.
- **In this session with file tools**, I produce a request to write a file, the system performs it, and you get a real downloadable file.

Identical model. The difference is entirely the body built around it.

### How ChatGPT does it

Normal chat mode and agent mode use a similar underlying model. Agent mode adds a browser, a loop, and confirmation steps. The extra ability comes from the wrapper, not from a smarter brain.

### In real products

The same model family powers a simple chat window and a full coding agent that edits repositories. Nobody changed the model. Somebody built a loop, tools, state and limits around it.

> **This is why "AI agent" is an engineering job, not a prompting job.**

## Where this lands in our build

The very first thing we build is the smallest honest version of that loop: **model → answer**, then **model → tool → result → model → answer**.

From day one it writes down every prompt, reply, tool call, cost and timing, so we can read back exactly what happened. Building the rest blind would be guesswork.

## Common mistakes

- **"We'll make it agentic with a better prompt."** No prompt adds a loop, a tool, or a stop button.
- **Leaving out the feedback step.** Running a tool but never showing the AI the result is the most common beginner bug. The AI then answers as if the tool never ran.
- **Building the loop with no limit.** The first bug everyone hits is an infinite loop with a real bill attached.
