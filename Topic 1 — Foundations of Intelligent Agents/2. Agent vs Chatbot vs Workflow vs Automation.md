
Imagine four helpers:

- **Automation** is a **vending machine**. Press B4 and you get chips. Every time, the same thing. It never thinks.
- **Workflow** is a **recipe card**. The steps are fixed: 1, 2, 3, 4. Sometimes one step says "taste it and decide if it needs salt," but the order never changes.
- **Chatbot** is a **friend you text**. They reply and give advice, but they don't go and _do_ anything for you.
- **Agent** is an **assistant you send to the market**. You say "get vegetables for dinner." If the first shop is closed, they find another one. They decide the steps themselves.

---

## Simple technical version

The one question that separates all four:

> **Who decides the next step: the programmer's code, or the AI?**

|Type|Who decides the next step|Uses AI?|Does real actions?|How many steps|
|---|---|---|---|---|
|**Automation**|Code (fixed rules)|No|Yes|Always the same|
|**Workflow**|Code decides the order; AI may help inside a step|Sometimes|Sometimes|Fixed path|
|**Chatbot**|Nobody; it just replies|Yes|No|One reply per message|
|**Agent**|**The AI**|Yes|Yes, using tools|Changes every time|

### Which one is better?

**None is always better.** Each has a trade-off:

- **Automation and workflows** are predictable, cheap, and easy to test. If you _can_ write down all the steps in advance, use these.
- **Agents** are flexible. They handle tasks where you _can't_ know the steps in advance. But they cost more, are harder to test, and can go wrong in surprising ways.

Simple rule:

> **Use the simplest one that gets the job done.** Only use an agent when the steps truly can't be written in advance.

## Real-life examples

### How Claude  does it

The same AI can be a chatbot _or_ an agent:

- If you ask me "what is 2 + 2?", I just reply. That's **chatbot mode**.
- When you asked for a note file, I used tools and took several steps. That's **agent mode**.

The AI is the same. What changes is the **system around it** (tools, loop).

### How ChatGPT does it

- Normal ChatGPT chat is a **chatbot**.
- ChatGPT agent mode (browsing websites, clicking, filling forms) is an **agent**.

### In real products

- **Automation**: a Zapier rule, "when an email with an attachment arrives, save the file to Google Drive." No thinking, same every time.
- **Workflow**: a support system where the AI reads a complaint and labels it "billing" or "technical," then fixed code sends it to the right team. The AI helps, but code decides the path.
- **Workflow engine**: **Temporal** runs fixed workflows reliably, even if a server crashes. You'll study it in P0 because our project borrows its crash-safety ideas.
- **Agent**: a coding agent deciding by itself which file to open next.

## In Agent Core

- We are building an **agent**, but with the **crash-safety of a workflow engine** like Temporal.
- That's why the roadmap says: **don't build fancy planning (Stage C) until P11 testing proves it's better than a simple loop.** Sometimes simpler wins.

## Say it to yourself

> "The difference is who decides the next step: code or AI. We only let the AI decide where the steps can't be written in advance. Otherwise a simple workflow is cheaper and safer."

---

## Common mistakes

- Building an agent when a simple workflow would work.
- Thinking "agent" automatically means "better" or "smarter."
