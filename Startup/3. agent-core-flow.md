# Agent Core — Complete Flow Reference

  

Every contract, what it takes as input, what it produces as output, and where that output goes next. Read top to bottom — this is the exact order things happen at runtime.

# SECTION 1 — THE OWNERSHIP HIERARCHY

  

These are the containers. They do not execute. They provide identity, configuration and scope to everything inside them.

# SECTION 4 — THE EVENT LOG

  

Every action above writes to the event log. This is the single source of truth. Everything else is derived from it.

  

```

┌─────────────────────────────────────────────────────────────────┐

│ EVENT ENVELOPE (wraps every event)                              │

│                                                                 │

│ INPUT                                                           │

│   event_type, run_id, step_id, tenant_id,                      │

│   principal, payload                                            │

│                                                                 │

│ OUTPUT (persisted, append-only, never modified)                 │

│   event_id, schema_version, event_type,                        │

│   run_id, step_id, tenant_id, principal,                       │

│   occurred_at, logical_clock (monotonic per run),              │

│   payload                                                       │

│                                                                 │

│ OUTPUT USED BY → AgentState (projection from log)               │

│                  REPLAY (reconstruct run, no re-execution)      │

│                  RESUME (reconstruct then continue)             │

│                  EVAL (replay recorded responses vs new code)   │

│                  Observability / Tracing                        │

│                  Evaluation / Golden Runs                       │

└─────────────────────────────────────────────────────────────────┘

```

  

**Events in the order they occur per run:**

  

```

RunCreated           → when a Run is created

StepStarted          → at the start of each Step

ContextAssembled     → when fragments are selected for this Step

ModelRequested       → before the API call

ModelResponded       → after the API call returns

ActionProposed       → when ActionProposal is parsed

PolicyDecided        → when PolicyGate makes its decision

ToolCallIntended     → BEFORE tool execution (dedup_key written here)

ToolCallCompleted    → AFTER tool execution

UnknownOutcome       → if process dies between Intended and Completed

ObservationRecorded  → when Observation is written

StepCompleted        → at the end of each Step

BudgetDebited        → whenever spend is recorded (tokens, cost, steps)

HumanInputRequested  → when agent needs human input

HumanInputReceived   → when human responds

RunCompleted         → when FINAL_ANSWER is reached

RunFailed            → when the run fails unrecoverably

```

# SECTION 11 — THREE RULES THAT NEVER CHANGE

  

```

TRUTH MODEL

  Event log   = truth          (append-only, never modified)

  AgentState  = projection     (derived from events, never primary)

  Checkpoint  = optimisation   (shortcut, not truth)

  

INTENT BEFORE EFFECT

  1. Write ToolCallIntended (with dedup_key) to event log

  2. Execute the tool

  3. Write ToolCallCompleted

  If process dies between 1 and 3 → UnknownOutcome event

  On restart → trigger tool's RecoveryPolicy, never re-execute silently

  

EXECUTION MODES

  REPLAY  reconstruct from log only — no model call, no tool call, ever

  RESUME  reconstruct then continue with new durable steps

  EVAL    recorded responses replace real ones — no network

```
